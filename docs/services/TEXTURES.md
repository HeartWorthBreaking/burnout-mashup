# `[bmashup.textures] version 1` - added front-end textures (platform 0.1.6)

Data only, no approval. Contract: the fetex1 interface (summarised here) and `CONTRACTS_CONTENT` s2 / s4. Tool:
`tools\fetex` (inspect / validate / extract / rebuild / pack). Examples: `examples\authored\fetex-art` (OCEANIA map art + a
garage photo, every pixel generated by `gen_art.py`), `examples\authored\bm-coupes\p43-coupe-photo` (the BM Coupe photo).

## Declaration (registration = presence only)
```toml
[bmashup]
platform = ">=0.1.6"
requires = ["bmashup.textures>=1"]

[bmashup.textures]
version = 1
txd = "art/mytex.txd"     # ONE texture dictionary in the mod folder (made with `fetex.py pack`); no "..", no absolute path
class = "frontend"        # the only class with external textures (car / track textures stay inside their model files)
```
- Every entry of the TXD is registered as `<mod-id>/<entry-name>` (entry names `[a-z0-9_.-]{1,31}`; a name twice: refused).
  Retail entries are `retail/<name>`: read only, never registered, never shadowed.
- A texture is USED only where a binding names it: a garage photo (`[bmashup.cars] photos`, `CARS.md`) or 4th-region map art
  (`[bmashup.wt_map_art]`, `WT_MAP_ART.md`). A texture-only mod registers; the car / map mod binds (cross-mod references need
  `requires_mods`).

## Limits (p4.3 decision M2: configured = allocated ceiling of ONE contiguous guest block)
| limit | value |
|---|---|
| texture pool (contiguous) | **12 MiB** (game peak measured ~38 MB of the 64 MB window) |
| entries in all mods | **768** |
| entries per mod | **256** |
| texture mods | 16 |
| bytes per entry | 1 MiB |
| photo bindings (all mods) | **512**; photos per car mod 256 |
| map slot bindings | 48 (one 4th-region map) |
Offline-tested at the bounds (p4.3 tests: photos 256 / 257 per mod, 512 / 513 in all). Runtime-demonstrated population: 17
textures / pool 561,152 B (gp_p43_2), 16,384 B (gp_p43_5).

## Lifetimes and failures
- Registry: host tables, process lifetime. Backing data: ONE contiguous block holding every admitted TXD, allocated at the first
  use, never freed or moved. Renderer: the toolkit's texture cache (per address + content hash).
- Reload: the game reloads Frontend.txd at every front-end set-up (after each race): bindings key on the CURRENT dictionary,
  nothing re-installed. A language switch re-installs bm_names' texts (offline-tested; not tried at runtime).
- Admission is transactional per mod (`TEX_DECL` own declaration / `TEX_REG` against earlier mods): nothing is installed before
  every check passes; the mod is "not usable" with the reason; other mods continue.
- First use without contiguous memory: every binding answers retail / the donor, logged once, counted (offline only: an
  allocation failure was not tried at runtime).

## Evidence
RUNTIME-VALIDATED on the fetex1 build (gp_fetex1_2: OCEANIA map art, a new marker, texts, an added car's own photo with paint
palettes, surviving the post-race reload) and on the combined host p4.3 (gp_p43_2: 12 mods, AUTHORED map / marker / HARBOUR
CITY / ticker; gp_p43_5: the AUTHORED BM Coupe photo). Registered paints recolour the photo since p4.3 fix 1 (runtime gp_vfix_1
on the fix slice build and gp_p44_1 on the final candidate p4.4).
