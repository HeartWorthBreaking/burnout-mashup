# Authoring tools in the mod kit

All pure Python 3.11+ (standard library only), portable since kit 0.4.1: they run from any folder, read YOUR OWN game data
only from the folder you give (`--game-data`, `docs\GAME_DATA.md`) and the kit's own vendored readers (`tools\_vendor`); a
missing prerequisite stops with exit 3 and the fix (`docs\PREREQUISITES.md`). Their outputs that contain retail-derived bytes
(donor parts) are LOCAL ONLY. Every tool's tests run from the kit: `tools\kit_selftest.py`. Exact versions: `docs\VERSIONING.md`
(the rows below give the 0.4.0 facts the ported tools keep; each tool's README lists its 0.4.1 changes).

## What is authored, what is borrowed (labels: AUTHORED / CONTROL / DERIVED / DONOR / FIXTURE)
- **carimport**: the body geometry, UVs, texture, paints, the optional wheel are AUTHORED; the collision hull, wheel positions,
  emitters, engine audio, physics and the crush skin basis are the DONOR's (labelled; local only).
- **trackbuild**: geometry, textures, collision, streamed units, LOD, PVS, route, grid, and (0.1.3+) traffic are AUTHORED; the
  Gamedata header + event records, enviro.dat (sky) and the audio banks are the DONOR's (default EU/M1_V1). Not unrestricted
  track creation. Off-track reset behaviour: INCONCLUSIVE at runtime.
- **fetex**: textures are what you pack (the examples' art is generated by code); never ship extracted retail art.
- **vehtool**: series / names / paints are AUTHORED; cars on `model = donor` ship no game data; fixtures are FIXTURE.
