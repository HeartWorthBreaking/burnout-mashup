# launcher/tests - tests of the launcher (Burnout Mashup identity)

Run from the repository root (Windows, Python 3.11+; tkinter for the window tests). Nothing here launches the game, needs game
files, or writes outside temporary folders. The test process points `%APPDATA%` / `%LOCALAPPDATA%` at fresh temporary folders
(`pubfix.py`), so a separate Takedawn install on the same PC is never read or written by a test.

| test | what |
|---|---|
| `test_launcher.py OUT.json [--gui]` | compatibility gate (incl. negative cases derived from the fixture's platform version), mod list, import, steps, window |
| `test_lifecycle.py OUT.json` | backup / clean / upgrade / verify / repair (`tools/uninstall.py`) with the bundle-local `profile\Roaming\BurnoutMashup` |
| `test_prepare_recovery.py OUT.json` | an interrupted prepare step never poisons the next run |
| `test_onboarding.py OUT.json` | the quickstart and tutorial do what they say |
| `test_diag.py OUT.json` | the diagnostics zip redacts user, computer, paths and holds no saves or game files |
| `test_exe.py OUT.json` | the launcher starter (needs a C compiler: `BMASHUP_CC`, `BMKIT_LLVM_MINGW`, or clang on PATH) |
| `test_resolutions.py OUT_DIR` | window layout at six display sizes (screenshots via `shot_launcher.py`) |
| `test_isolation.py OUT.json` | with a fake `%APPDATA%\Takedawn` and `%LOCALAPPDATA%\Takedawn` (temporary folders), prepare, play `--print-env`, remove / uninstall, diag and the mod operations leave them byte-identical, never open anything below them, and never take approvals from them |
| `test_build.py OUT.json` | Build Mashup without a real build: inputs (game folder, other game / region / revision, disc images incl. truncated), tools (missing -> offers; pins = `tools/prepare_deps.py`), downloads through a local mock server (OK, 404, wrong sha256, interrupted, not confirmed), refusals (input, tools, low disk, read-only folder, inside the checkout, lock), install / previous build / switch back / the Play rule, the Build window and the launcher window (headless). Optional: `BM_TEST_XBE`, `BM_TEST_TOOLCHAIN`, `BM_TEST_DL_DIR` |
| `test_build_isolation.py OUT.json` | every `bmbuild.py` command (and a whole build with `BM_TEST_XBE`, `BM_TEST_TOOLCHAIN`, `BM_TEST_TD`, `BM_TEST_XR`) under the audit hook with a fake Takedawn environment: nothing below it is touched; the build steps get a minimal environment |
| `test_build_real.py OUT.json --input GAME --toolchain DIR --work DIR ...` | REAL builds through the launcher CLI: clean, warm (all reused), cancel during regen + process-tree kill during compile + resume, incremental (one script / one layer file changed), verify failure and install failure (previous build kept). Several minutes; installs into this checkout's `launcher\host-local` |
| `test_update.py OUT.json [--work DIR]` | the updater without a real build (local mock channel, TEST keys of `upd_testkit.py`, synthetic sources / builds): RFC 8032 vectors, ssh-keygen interop, no channel configured, good update + switch back, tampered archive, unknown key, bad signatures, downgrade / install-older, replay, incompatible minimum, interrupted / cancelled downloads, failed / cancelled builds, offline, upstream refused, unsafe archives, no network unless asked (socket audit hook), isolation, the Updates window, the shipped configuration trusting exactly the release key |
| `test_update_real.py OUT.json --input GAME --toolchain DIR --work DIR ...` | the updater with REAL builds in copies of this checkout under DIR: update from a signed (TEST key) new version, clean build from the new source, exe = the manifest's reference, previous kept, switch back / forward, failed rebuild, cancel during compile + resume. Several minutes |

`fixtures/HOST_INFO_fixture.json` is a HOST_INFO.json GENERATED by `build/host_info.py` from a real, verified build of this source
tree (identity `bmp-0.1.9+6f17b9e08be3`; the fork's clean-checkout reconstruction, regenerated after `build/EXPECTED.json` gained the release reference): it carries the exe's sha256, the platform
version, services, tables, plugin api and, per field, the source it came from. It is test data only (the exe is not in this
repository). Regenerate it with `build/host_info.py` after a new build; the tests derive their expectations from it.
`test_nobuild.py` checks the launcher and the Workbench without any HOST_INFO.json. `audited.py` and `isolation_ops.py` support `test_isolation.py`.
